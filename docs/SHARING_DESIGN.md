## 一 产品目标与范围

每条已发布内容都拥有一个永久链接。作者或读者将链接粘贴到 Telegram 后，聊天中的预览能显示这条内容的文字摘要及适用的图片。读者打开链接后，进入 yuki.art 的连续时间线，对应内容出现在可见区域中间，随后可以向上看更新的内容，向下看更早的内容。

本期交付五项功能：永久链接、逐条分享元信息、极简分享按钮、打开链接后的准确定位、与既有功能的兼容。首页继续展示从新到旧的完整时间线，UTC 排序、侧栏、深浅色切换、图片查看器和页脚继续使用现有设计。

本期不增加分页界面、评论、账号、点赞、转发计数、标签、搜索或 Telegram 自动发帖机器人。不引入新的前端框架、数据库和常驻服务。Telegram 的 Instant View 全文阅读也不属于本期交付。

“Telegram 解析出内容”在本项目中指链接预览卡片。卡片可展示标题、描述和媒体，具体排列及截断由 Telegram 决定；网站提供准确的源数据，完整正文在网站阅读。不能承诺任意长文全部展开在 Telegram 消息里。[Telegram 网页预览结构](https://core.telegram.org/constructor/webPage)

## 三 用户旅程

### 作者分享一条内容

1. 作者通过现有后台发布内容。
2. GitHub 内容提交触发 Pages 构建，构建同步生成这条内容的永久链接。
3. 在时间线找到内容，点击其分享按钮。
4. 支持原生分享的设备打开系统分享面板；其他情况下复制永久链接。
5. 将链接发送到 Telegram，Telegram 抓取该链接并生成对应预览。

### 读者从 Telegram 进入

1. 点击预览中的链接。
2. 浏览器直接得到包含完整时间线和对应元信息的静态页面。
3. 页面首次进入时定位到被分享内容；短内容居中，长内容展示开头。
4. 对应内容出现一次轻微背景提示。
5. 读者上下滚动，按 UTC 顺序继续阅读。

### 读者在站内继续分享

读者滚动到另一条内容后，点击那一条的分享按钮。复制或分享的必须是被点击内容的永久链接，不能复用当前地址栏里的原始入口链接。

## 四 永久链接与内容身份

采用以下固定结构：

```text
https://yuki.art/p/<postKey>/
```

`postKey` 定义为 Markdown 文件 basename 去掉 `.md`，完整保留时间戳、毫秒和现有唯一后缀。已有文件的 8 位或 32 位后缀均保留。不使用正文、标题、列表索引或排序位置生成身份。

真实文件示例：

```text
content/2026/10/2026-10-01T12-56-44.177Z-ff2a5da7937043908c5f44bd77a4229c.md

https://yuki.art/p/2026-10-01T12-56-44.177Z-ff2a5da7937043908c5f44bd77a4229c/
```

此结构无需作者手写 slug，也无需给旧内容补 Front Matter。正文修改、新增其他内容、时间线排序变化都不会改变该内容的 URL。重命名文件会改变内容身份，README 中要说明：普通正文编辑应保留文件名。

必须集中实现身份函数，建议职责如下：

```text
postKey(post)       -> 稳定的文件身份
entryId(post)       -> 保留既有 DOM 锚点身份
postPath(post)      -> /p/<postKey>/
postUrl(post, site) -> 生产 HTTPS 绝对 URL
```

构建时校验 `postKey` 唯一性。出现冲突应明确报错，不能让后生成的页面覆盖前一个。

| URL 情况 | 目标行为 |
| --- | --- |
| `/` | 正常首页，从时间线顶部浏览 |
| `/p/<有效 postKey>/` | 返回该内容的分享页面并定位 |
| `/p/<不存在的 postKey>/` | 真正的 404，不伪装成首页成功 |
| `/#entry-…` | 旧分享链接继续定位到原内容 |
| 分享页带查询参数 | canonical 和复制链接仍为干净的永久链接 |
| 分享页带有效内容锚点 | 显式锚点优先于默认分享目标 |
| 分享页带 `#top` | 跳到顶部，不能再次拉回分享内容 |

采用尾斜杠作为规范地址。在 Pages 环境验证无斜杠和显式 `index.html` 的平台规范化结果，避免额外增加多跳重定向。生成的 canonical、OG URL、RSS 和分享按钮统一使用同一个规范地址。

## 五 静态页面与构建方案

本期采用构建时生成静态分享页。每个分享页使用同一套时间线模板与完整内容列表，仅页面元信息和初始定位目标不同。

```text
dist/
  index.html
  404.html
  p/
    <postKey A>/index.html
    <postKey B>/index.html
  style.css
  theme.js
  image-viewer.js
  quick-browse.js
  post-sharing.js
  feed.xml
  sitemap.xml
  robots.txt
  social-card.png
  images/...
```

所有脚本、图片和样式使用站点根路径或正确的绝对 URL。深层路径打开时不能请求 `/p/<postKey>/style.css` 或 `/p/<postKey>/images/...`。

在首页和所有分享页中，文章数量、顺序、日期分组、正文和侧栏应一致。每条文章的 DOM ID 唯一。分享页 body 使用安全转义后的 `data-initial-entry` 标明目标 DOM ID，首页没有默认定位目标。

脚本作为外部文件加载，并沿用现有内容 hash 版本参数。不加入内联脚本，不修改 CSP 为 `unsafe-inline`。新脚本应允许单独失效；失效时正文、图片、时间戳永久链接仍可使用。

Cloudflare Pages 可将匹配路径的 HTML 作为静态页面提供；保留顶层 `404.html`，使不存在的分享地址按正常 404 处理。[Cloudflare Pages 路由与 404 文档](https://developers.cloudflare.com/pages/configuration/serving-pages/)

这一方案适合本期小型静态站点，但 N 篇内容各输出完整 N 篇时间线，HTML 总输出量会随 N 大致按平方增长。实施者必须在交付记录中报告文章数量、首页 HTML 大小、全部分享页大小和构建耗时。本期共享 CSS、JS 与图片，不把这些资源复制进每条目录。未来内容规模扩大时，可独立规划按需加载相邻内容；不要在本期偷偷实现无限加载或替换为动态服务。

## 六 Telegram 与 X 分享元信息

每条分享页在原始 HTML 的 `<head>` 中输出专属于目标内容的元信息。不能依赖执行 JavaScript、Cookie、作者登录或按 User Agent 分流。

| 字段 | 分享页取值 |
| --- | --- |
| `title` | 内容标题加作者名 |
| `meta description` | 目标内容的纯文本摘要 |
| `link rel=canonical` | 该条永久链接 |
| `og:type` | `article` |
| `og:site_name` | `site.json` 中的作者或站点名 |
| `og:locale` | 与现有站点一致 |
| `og:title` | 自动提取的内容标题 |
| `og:description` | 目标内容摘要 |
| `og:url` | 该条永久链接 |
| `og:image` | 适用图片的绝对 HTTPS URL |
| `og:image:alt` | 原始图片说明或默认图片说明 |
| `article:published_time` | 文件名解析出的 UTC ISO 时间 |
| `twitter:card` | 有适用正文图时 `summary_large_image`，默认品牌图时 `summary` |
| `twitter:title` | 与内容标题一致 |
| `twitter:description` | 与内容摘要一致 |
| `twitter:image` | 与 Open Graph 图片一致 |
| `twitter:image:alt` | 与 Open Graph 图片说明一致 |

只在确实知道尺寸、格式时输出 `og:image:width`、`og:image:height` 和 `og:image:type`。不要猜测原图尺寸，也不要用发布时间伪造内容修改时间。首页继续保留站点自己的标题、介绍、品牌图和首页 canonical。

Open Graph 的基础属性与图片描述遵循公开协议；本项目把内容摘要作为 `og:description` 提供给支持的分享客户端。[Open Graph 协议](https://ogp.me/)

### 标题与摘要提取

复用 MarkdownIt 解析得到的 token，提取文本内容。不要只靠正则去除 Markdown：链接、图片、转义字符、代码和标记嵌套可能使结果错误。

标题规则按以下顺序执行：

1. 取第一个非空 heading 的纯文本；没有 heading 时，取第一个含可读文本段落的第一行。
2. 排除独立图片、视频裸链接和只有 URL 的行。
3. 标题最多 48 个 Unicode code point，超过时加省略号；中文和 emoji 不切坏代理对。
4. 没有可读正文时，回退到“图片记录”或“媒体记录”，并带 UTC 日期与时间区分内容。

摘要从全部可读正文按原顺序提取，保留文本信息，将连续空白规范化为一个空格，最多 200 个 Unicode code point，超过时加省略号。摘要可包含标题所在段落，以免短内容失去唯一正文。不要使用通用站点介绍替代一条有文字的内容。

普通行内链接保留链接文字，不把正文中的描述一并丢弃。含图片且已有正文时，图片 alt 不混入摘要；只有图片时，采用可读 alt，仍没有说明则回退到“图片记录 · UTC 日期时间”。只有视频链接时，采用“视频记录 · UTC 日期时间”。代码中的纯文本可进入摘要，但去掉格式标记。

所有属性都必须 HTML 转义，特别覆盖引号、`&`、`<` 和 `>`。不要把正文或 URL 拼成可执行 HTML。

### 图片选择

按内容顺序选第一张可用的站内正文图片。检查图片真实存在于本次输出中，并将 URL 解析为生产域名上的绝对 HTTPS 地址。优先处理现有 `public/images/` 中的图片；图片格式根据实际文件和部署可访问性验证。

没有适用图片、只有视频、图片缺失或图片格式不适合预览时，回退到现有 `/social-card.png`。不以 SVG 字标作为社交预览图。不强制裁剪正文图，不增加作者填写封面的步骤。

本期不在构建时从任意外部 URL 下载图片，不全局放宽当前站内图片 CSP。对已有外部图片引用使用品牌图回退，并在交付中说明。若 Telegram 对某个现有图片格式实际解析失败，可以把那张站内图生成兼容 JPEG 或 PNG 预览副本；此项以真实失败为依据，不预先引入图片处理依赖。

### 平台边界

Telegram 和 X 可能缓存已有预览、截断摘要、选择不同媒体大小。正确 HTML 和图片响应是网站端验收，真实聊天卡片是平台端验收，两者分别记录。不得把伪造 User Agent 的 HTTP 成功宣称为真实 Telegram 卡片已经成功。

## 七 分享按钮的视觉与操作

将每条内容的时间信息和分享按钮放在同一行：时间靠左，操作靠右，正文紧随其后。保持现有内容宽度、字体、色彩与条目间距。

```text
12:56 UTC                                      [分享图标]

史莱姆想要，史莱姆得到！

现在的 AI 应该是最好用的时候了……
```

设计参数是本项目的产品选择，实施者可为像素对齐小幅调整，但不能缩小触控区域：

| 项目 | 规格 |
| --- | --- |
| 图标 | 内联 SVG 分享或链接图标，统一细描边，禁止 emoji 图标 |
| 图标可视尺寸 | 18 CSS px 左右 |
| 点击区域 | 至少 44 × 44 CSS px；这是本项目采用的易点击尺寸 |
| 静态状态 | 透明背景，使用现有 muted 颜色，始终可见 |
| Hover | 颜色稍加强，必要时增加很浅的背景 |
| 键盘焦点 | 清晰的 `:focus-visible` 轮廓 |
| 触控 | 有按压反馈，不依赖 hover 才能发现 |
| 无障碍名称 | “分享这条内容”，可带 UTC 时间区分多条 |
| 成功反馈 | 简短“链接已复制”，使用 `role=status` 或礼貌 live region |
| 反馈显示时间 | 约 2 秒，新的操作替换旧反馈 |

分享按钮必须是真正的 `<button type="button">`，使用 Enter 和 Space 激活。时间戳同时改为指向该条永久链接的普通 `<a>`，以提供无 JavaScript、复制链接地址和新标签打开的标准入口。按钮在脚本初始化后才启用；JavaScript 关闭时，时间链接仍可用，不显示失效按钮。

原生分享调用只提交目标条目的 `title` 与永久 `url`，避免把摘要重复塞入消息正文。优先调用存在且支持该数据的 `navigator.share`；API 不支持时复制链接。系统分享需要用户操作触发，不能异步等待其他网络操作后才打开。[Web Share API 文档](https://developer.mozilla.org/en-US/docs/Web/API/Navigator/share)

原生分享被用户取消时，静默结束，不自动复制、不提示失败。其他错误可以尝试复制链接。分享 Promise 完成也不表示对方已经收到消息，不显示“已发到 Telegram”。

复制优先使用 Clipboard API。权限拒绝或浏览器不支持时，显示一个紧凑的可选中文本区域，包含完整链接和“请复制链接”的提示，支持关闭与键盘操作；不能只弹出模糊错误，也不能无条件声称已经复制成功。该区域可以原位展开，避免新增全屏弹窗与图片查看器冲突。

移动反馈显示于底部安全区之上，并避开现有快速浏览底栏；桌面反馈可放在正文区域底部。使用 `env(safe-area-inset-bottom)` 处理设备安全区域。减少动态效果偏好开启时，取消非必要动画。

## 八 分享内容进入视口的规则

“出现在时间线中间”定义为进入后在视口中突出目标内容；内容的时间顺序和所在 DOM 位置不改变。

### 确定初始目标

页面首次加载时按优先级选择目标：

1. URL 中存在有效显式锚点时，遵循锚点；`#top` 和跳到内容链接保持自身语义。
2. 没有有效显式锚点的分享页，使用 `data-initial-entry`。
3. 首页没有目标时，保持普通顶部进入。

浏览器前进、后退、BFCache 恢复和同一分享页刷新应优先保留浏览器已有的阅读位置，不强制再次回到入口文章。使用现有浏览器恢复机制，按需要识别导航类型；不要全局设置 `history.scrollRestoration = 'manual'`。

### 定位算法

有效阅读视口高度 V 应扣除真正覆盖内容的底部浏览栏与安全区；随移动浏览器 UI 变化可参考 `visualViewport`。测量目标 article 高度 H：

- H 不超过 V 的 70%：将 article 的几何中心放到有效阅读视口中心。
- H 超过 V 的 70%：将 article 开头放到有效阅读视口顶部以下约 16% 的位置，先展示时间和正文开头。
- 最终滚动值 clamp 到文档可滚动范围；最新和最早内容靠近页面边缘时允许无法严格居中，不插入大块空白，不改变内容顺序。

首次定位使用即时滚动，避免读者看到从首页顶部穿过大量文章的长距离动画。目标条目可有约 500 毫秒的淡背景提示；不增加持久粗边框、彩色卡片或“精选”样式。脚本定位应有专门的状态 class，不能只依赖 `:target`，因为分享路径可以没有 hash。

### 图片和字体导致的布局变化

应尽可能为站内图片写入已知的宽高或正确比例，保持 `height: auto`，减少目标前面内容加载时的位移。只使用可确定的真实尺寸；增加解析工具前先检查项目可复用能力。

先在 DOM 可用时定位，再允许一个短暂的定位修正窗口：最长 2 秒。期间只对布局变化触发的测量做合并处理；误差超过 16 CSS px 时修正，不进行无止境逐帧滚动。可使用 ResizeObserver 和字体就绪通知，修正窗口关闭后解除观察器。

一旦用户滚轮、触摸、拖动滚动条或使用滚动按键，立即结束自动修正。页面不能在读者已经开始读其他内容后突然跳回分享内容。不能等待所有历史懒加载图片加载完后才展示目标，也不能为了定位把所有媒体改成 eager loading。

### 站内导航与地址栏

上下自然滚动不持续修改地址栏、不向历史堆栈添加每条文章。每条分享按钮自行携带所属条目的永久 URL。

快速浏览侧栏继续跳到对应条目，使用与分享定位一致的短内容居中、长内容看开头逻辑；用户主动跳转可用短平滑滚动，减少动态效果时即时滚动。保留标准锚点链接和历史行为，不把键盘激活与鼠标点击实现成两套不一致的逻辑。

旧 `/#entry-…` 链接继续有效。主页上的旧锚点也可以获得新的定位体验，但旧链接不被悄悄当成新的逐条元信息页面。

## 九 无障碍与兼容要求

首次视觉定位不得把焦点抢到分享按钮、自动打开对话框或使读屏软件反复朗读整条文章。站内用户主动定位时可让条目成为程序化可聚焦元素，确保焦点可见且没有覆盖。

所有操作按钮有明确名称，图标设置 `aria-hidden="true"`。反馈只朗读一次，复制失败后可用键盘选中和复制链接。浅色、深色、200% 缩放以及窄屏都必须保留可读正文与可操作按钮。

JavaScript 关闭时，分享页仍包含原始正文和准确元信息，时间戳永久链接可用。首次居中定位属于脚本增强；不要用 meta refresh 掩盖缺少实现。

测试桌面 Chrome 与 Safari，移动 Safari 与 Chrome；如果当前执行环境缺少真实设备，报告缺少哪些验证，不能把模拟视口描述成真实设备测试。Telegram 内置浏览器也需实际检查，若当前无法访问 Telegram，则保持待验证状态。

## 十 内容生命周期与既有功能

新内容通过现有后台写入 Markdown 并提交 GitHub 后，由同一次 Pages 构建自动生成首页、逐条链接、RSS 和 sitemap，无需手工追加 URL 配置。

编辑正文后永久 URL 保持，下一次构建更新摘要、图片和所有时间线副本。删除内容后，其分享文件在重新构建中消失，站点返回 404；Telegram 可能仍显示缓存的旧卡片，不能把平台缓存等同于站点仍在提供内容。

RSS 新条目的 `link` 使用新的永久 URL。已上线 RSS 的 `guid` 继续沿用旧身份字符串，避免阅读器把所有历史条目当作新内容：保留既有的首页锚点 GUID，修改 `link` 即可。本期新增内容也使用相同的旧 GUID 计算规则维持一致性，GUID 和 `link` 可以不同。

sitemap 加入所有有效永久链接，继续保留首页。不要使用发布时间冒充文章修改时间；无可靠修改信息时，条目可省略 `lastmod`。

图片全屏查看器必须在深层页面同样可用。关闭图片返回用户打开查看器前的时间线位置，不能再次触发初始定位。正文单回车、代码块、列表、blockquote 和视频嵌入都要检查。

首页页脚继续使用现有版权、UTC、RSS 和回到顶部。深层分享页的回到顶部操作在当前时间线生效。用户自然滚动后点击另一条内容的分享按钮，分享目标必须随被点击条目变化。
